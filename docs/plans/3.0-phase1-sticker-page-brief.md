# StickerHunt 3.0 — Бриф: сторінка стікера (фаза 1)

**Статус:** ЧЕРНЕТКА від 2026-10-25 (скіл `/i-shape`, дискавері пройдено, бриф чекає підтвердження Віктора). Код не пишемо. Контекст: `3.0-phase0-personas-usecases.md`.
**Не зроблено:** `DESIGN.md` (дизайн-ДНК) ще не існує, його створює Hallmark Study окремим кроком. Тому «Design Direction» нижче це напрям, а не візуальна специфікація.

## 1. Резюме фічі
Нова сторінка стікера для фаната клубу, який прийшов з пошуку на телефоні. Показує стікер, автора й веде далі по клубу. Верстка рендериться клієнтським шаром поверх тих самих статичних URL (регенерації нема). Це частина фази 1 «додавання стікерів»: на сторінці зʼявляється авторство (сіяні акаунти й живі внесники).

## 2. Головна дія
**Піти далі по стікерах цього клубу.** Фан прийшов за своїм клубом, тому природний наступний крок: гортати галерею клубу прямо зі стікера. (Обрано Віктором 25.10; підстава: клубні запити в GSC і DataForSEO.) Усе інше на сторінці другорядне.

## 3. Напрям дизайну
- Відчуття (обрано): **швидко й легко на телефоні** + **вулична, фанатська енергія**.
- Антицілі: не шаблонний «AI-вигляд»; не v4 street/zine (відкинуто Віктором); не важкий і не повільний.
- Стиль виводимо через Hallmark Study у `DESIGN.md` для StickerHunt; до цього конкретних кольорів, шрифтів і форм тут не фіксуємо.
- Якір напруги, який дизайн мусить розв'язати: «вулична енергія» без перетворення на шум і без шаблонності.

**Антиреференси (Віктор 25.10):** НЕ потрібні: фільтри-форми на першому екрані; попапи й промо-банери поверх контенту; стерильний «корпоративний» вигляд; темна тема за замовчуванням. Референси-кандидати (скріни 390×844: Letterboxd, FotMob, Atlas Obscura, Vivino, slapstickers.org). **Обрано Віктором 25.10: FotMob, «легко, просторо».** Напруга для дизайну: з FotMob беремо легкість, простір і mobile-first структуру; НЕ беремо стерильність (виключена антиреференсом). «Вулична енергія» має прийти з фото стікерів, типографіки й характеру, а не з рамок і жорстких тіней v4.

## 4. Стратегія розкладки (високий рівень, mobile-first)
1. Стікер домінує: велике зображення перший екран, найменше хрому навколо.
2. Одразу під ним ідентичність (клуб, країна) і **смуга «ще стікери цього клубу»**: це головна дія, її видно без прокрутки там, де можливо.
3. Автор: компактний рядок, другорядний, веде в профіль.
4. Факти (де знайдено, коли), карта, схожі стікери: нижче, у порядку важливості для фана.
5. Горизонтальний ритм і розмір цілей під великий палець; десктоп розширює, а не змінює логіку.

## 5. Стани
| Стан | Що бачить користувач |
|---|---|
| Типовий | Повна сторінка, автор і смуга клубу |
| Клієнтський шар завантажується | Статичний HTML уже повний і читабельний; шар доповнює без стрибка верстки (бюджет CLS ≤ 0.1) |
| JS не спрацював / повільна мережа | Статична сторінка як є: текст, зображення, JSON-LD, посилання |
| Автор невідомий або «архівний» | Нейтральний підпис, без битого посилання |
| Клуб має 1 стікер | Смуга не порожня і не обманює: показати сусідні клуби країни |
| Нема локації (близько половини) | Карту ховаємо без «дірки» |
| Дуже довга назва клубу / багато чи нуль схожих | Без перелому верстки |
| Стікер знято (`active=false`) або видалено | ❓ Рішення: 410, редирект на клуб, чи «знято» |
| Залогінений внесник із `can_edit` | Додаткові дії керування; не плутати з фанатським виглядом |

## 6. Модель взаємодії
- Тап по смузі клубу веде до іншого стікера; гортання по горизонталі, повернення «назад» ставить на попередній стікер.
- Тап по автору веде в публічний профіль (окремий екран, окремий бриф).
- Додавання стікера й створення клубу: окремі екрани для внесників, не частина сторінки фана (окремий бриф).
- Фідбек швидкий і без блокуючих модалок.

## 7. Вимоги до змісту
- Мова інтерфейсу: ❓ сайт англомовний; підтвердити.
- Потрібні мікротексти: підпис автора («Added by …»), стан «архів», порожні й помилкові стани, назва смуги клубу.
- Реальні діапазони: у клубі від 1 до багатьох десятків стікерів; близько половини без локації; 59 країн, 819 клубів, 4783 стікери.

## 8. Рекомендовані референси для реалізації
`spatial-design`, `interaction-design`, `responsive-design` з impeccable; після коду обовʼязково `/frontend-checklist` і `/ui-gates` (контраст, скрол @280/320/414, цілі, CLS). За памʼяттю Віктора: focus-кільця й keyboard-a11y не форсити як critical.

## 9. Відкриті питання
1. ✅ Метрика успіху (Віктор 25.10): частка відвідувачів сторінки стікера, що відкрили ще один стікер. ❓ Лишається вимір: подія в аналітиці (PostHog), відправна точка, поріг «добре».
2. ❓ Hallmark Study → `DESIGN.md` для StickerHunt (передумова візуалу).
3. ✅ Мова копі: тільки англійська, як зараз (Віктор 25.10).
4. ✅ Знятий стікер (`active=false` або видалений): редирект 301 на сторінку клубу (Віктор 25.10). ❓ Потребує перевірки, як редирект реалізується без регенерації (vercel.json чи клієнтський).
5. ❓ Окремі брифи: профіль автора; додавання стікера; створення клубу.
6. ❓ Як вшитий inline-скрипт сторінки (15 КБ, edit-кнопка тощо) уживається з клієнтським шаром.
7. ❓ Приклади сайтів, які Віктору подобаються («легко на телефоні» і «вулична енергія»).
