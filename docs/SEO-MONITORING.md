## Методика циклу

### Крок 0 — що змінилось (до будь-якого збору даних)
1. **Репо:** `git fetch origin && git status` у StickerHunt. Лічильники сторінок брати з `origin/main`, не з локального дерева (03.08 локальний чекаут відстав на 68 комітів, приріст занизився). Подивитись коміти з попереднього циклу: що зробили у вікні.
2. **Сторонні події Google:** `curl -s https://status.search.google.com/incidents.json` (апдейти з датами `begin`/`end`). Без цього цифри читаються хибно (13.09 spam update, 23.11 core update).
3. **База знань SEO** (`~/Claude Code/ops/seo-kb`): `git log --since=<дата попереднього циклу>`, `INDEX.md`, відкриті `conflicts/V-*.md`, `inbox/`, `tools/GAPS.md`. Кожен новий claim про technical / ai-search / backlinks — або додати перевірку в цикл, або записати у звіті, чому ні. Якщо база суперечить методиці — не міняти мовчки, спитати Віктора. Відомий приклад: CLM-0323 (краулер 403 при Googlebot 200 = спершу бот-правила/WAF хоста).

### Крок 1 — GSC, WEB + IMAGE
Вікно ЗАВЖДИ = дата звіту −31 … −3 дні (29 днів). `gsc_check.py analytics` бере end=вчора, це НЕ те вікно: робити інлайн-запит через `_query(svc, start, end, ...)` з `scripts/gsc_check.py` (приймає `datetime.date`, не рядок). Запускати `python3` з PATH (python.org 3.11 з модулем `google`); `/opt/homebrew/bin/python3` і `/usr/bin/python3` модуля не мають. `SSL_CERT_FILE=/etc/ssl/cert.pem`.
Брати: кліки, покази, CTR, позицію; денний ряд; топ-сторінки і топ-запити; розклад показів за типом сторінки (stickers / clubs / countries / cities / інше). Service account `~/.config/gsc_credentials.json`, property `sc-domain:stickerhunt.club`.

### Крок 2 — URL Inspection діагностичних URL
`python3 scripts/gsc_check.py inspect <urls>`: `/`, `/catalogue.html`, `/clubs/617.html` (флагман, індикатор «бюджет верхівки живий»), `/stickers/3201.html`, `/clubs/1095.html` (глибокі). Брати verdict, coverageState, lastCrawlTime. Країни — це `countries/TUR.html` (ISO-код), не `countries/turkey.html`.

### Крок 3 — сайтмепи
`python3 scripts/gsc_check.py sitemaps`: `contents[image] submitted`, `isPending`, `lastDownloaded`, errors. Поле `indexed=0` в API — не сигнал. Окремого `sitemap-images.xml` нема і не планувалось: картинки inline у `sitemap-stickers-*.xml`. Індексний `sitemap.xml` давно isPending — не блокер, шарди подані поштучно.

### Крок 4 — внутрішні лінки
`node scripts/internal-links-audit.js` → кількість ізольованих клубів і стікерів (звіт пишеться сам у `seo-reports/`).

### Крок 5 — CWV

### Крок 6 — crawl-diff (seoskill)
Що змінилось у розмітці між замірами. Запускати у фоні першим ділом (~30–40 хв), **один прогін, вивід в окремий файл** (09.11 два прогони писали в один файл і змішались):
```bash
. ~/.nvm/nvm.sh && nvm use 22        # системний Node 20 не запуститься
export DO_NOT_TRACK=1
seo reports run crawl-diff --params '{"startUrl":"https://stickerhunt.club/","limit":8000}' --json > <файл>.json
```
- **Ліміт 8000, щоцикла однаковий.** `crawled` мусить бути МЕНШИЙ за `limit`, інакше краул обрізаний і диф покаже «зниклі» URL, яких ніхто не видаляв. Дивитись також `warnings`, `outputBudget.truncated`.
- Вивід = кандидат, не факт: кожну знахідку звіряти вручну (grep / curl / `git log --all`). Цінність — у сирих `items[].before/after`, не в `recommendations` (13.09 реальна дірка h1 сиділа в `low`). CLI віддає лише 5 items; при масових змінах доповнювати скриптом по h1/title у файлах.
- Відомі давні 404 від генератора (не регресія): `cities/riga|tallinn|dubrovnik|milan|pendik.html`, `countries/.html`.
- GSC-логін не потрібен (`seo start` не запускати). Памʼять: `reference_seoskill_cli`.
